Миграция `20261117T1940_avatars_and_groups` добавляет только шесть полей:

## Аватарки

Мой профиль открывается нажатием на аватарку внизу боковой панели. Нажатие на
аватарку в профиле открывает редактор: выбор JPEG/PNG/WebP до 10 МиБ, круглый
предпросмотр, масштаб и положение области по двум осям, сохранение/отмена/удаление.
Обрезка доступна мышью, клавиатурой и ползунками на телефоне.

На сервер передаётся оригинал и нормализованные координаты. Sharp проверяет
фактический формат, декодирует изображение, учитывает EXIF orientation, проверяет
область в пикселях и формирует квадратный WebP 512×512 без исходных метаданных.
Лимит декодирования 40 млн пикселей; анимированные изображения не принимаются.
Оригинал аватарки не сохраняется. Готовый файл получает случайный UUID и хранится
в приватном uploads/avatars, не в public.

POST/DELETE /api/profile/avatar меняют только запись авторизованного пользователя.
POST/DELETE /api/groups/:id/avatar требуют owner/admin. Проверка повторяется внутри
транзакции под блокировкой профиля/группы. Произвольный URL из клиента не принимается.
GET /api/avatars/:filename требует входа: пользовательские аватарки видны
зарегистрированным пользователям, групповые — только текущим участникам группы.
Файлы, не связанные с текущей аватаркой в БД, не выдаются.

После commit старая аватарка удаляется только после проверки отсутствия ссылок в
User/Conversation. Сбой удаления логируется; при включённой фоновой очистке раз в
час повторно рассматриваются неподключённые UUID-файлы старше 24 часов. Неизвестные
имена/симлинки не обходятся. Временный share-режим отключает плановую очистку,
но замена/удаление аватарки всё равно выполняет немедленную проверку и очистку.

profile-updated передаёт только публичные id/username/avatarUrl. Клиент обновляет
профиль, заголовок, сообщения, список диалогов, поиск и участников без перезагрузки.
Кэш профилей не даёт поздней истории вернуть старую аватарку. Аудио/видеоплееры не менялись.

## Группы

Кнопка «Создать группу» открывает название и поиск/выбор участников. При создании группа
содержит от двух до 50 пользователей, включая создателя; после выходов может остаться один владелец. Опциональная аватарка
настраивается следующим шагом после создания, с тем же редактором обрезки.
Нажатие на заголовок/аватарку группы открывает сведения и список участников.

| Действие | Владелец | Администратор | Участник |
|---|---|---|---|
| Сообщения, вложения, история | Да | Да | Да |
| Название и аватарка | Да | Да | Нет |
| Добавление участников | Да | Да | Нет |
| Исключение обычного участника | Да | Да | Нет |
| Исключение администратора | Да | Нет | Нет |
| Назначение/снятие администратора | Да | Нет | Нет |
| Передача владения, удаление группы | Да | Нет | Нет |
| Самостоятельный выход | После передачи владения | Да | Да |

Владельца исключить нельзя. При передаче прав прежний владелец становится
администратором. Самовыход владельца отвергается сервером: сначала передать
владение либо удалить группу. Все мутации состава/ролей сериализуются блокировкой
conversation:ID в PostgreSQL; отправка/изменение/удаление сообщений использует ту
же блокировку и повторную проверку участия. Клиент не может назначить себе роль.

Удаление группы мягкое: она скрывается у всех, её история и вложения недоступны,
а данные сообщений сохраняются в PostgreSQL. Восстановления удалённой группы в UI
нет. Это не физическое стирание истории и не удаление пользовательских файлов наугад.
Аватарка удалённой группы отвязывается и очищается безопасно.
Новый участник видит всю сохранённую историю группы; отдельной политики «только с
момента вступления» в версии 1.0 нет.

## Доставка и отзыв доступа

Сохраняются комнаты general, user:ID и conversation:ID. Для групп используются те
же conversation rooms и подписки, что и для личных чатов. При смене состава сервер
сверяет БД, присоединяет актуальные сессии и удаляет исключённые из комнаты,
рассылает conversation-revoked и обновление списка только затронутым пользователям.
Приватная доставка дополнительно выбирает текущих участников из БД и адресует
событие их user rooms: устаревшее членство в conversation room не даёт получать данные.

История, подписка, отправка, изменение/удаление и файлы независимо проверяют доступ.
Автор загрузки имеет доступ к неопубликованному файлу, но после публикации проверка
идёт через доступные сообщения. Исключённый участник не может скачать даже собственный
ранее опубликованный групповой файл. Уже скачанные байты технически отозвать нельзя.
Удалённые группы не разрешают чтение по старому URL.

Клиент при отзыве доступа закрывает сообщения/плееры и блокирует отправку. Версия
запроса истории увеличивается: запоздалый HTTP-ответ или ACK не восстанавливает
приватный контент. После повторного добавления историю можно получить заново.
Сообщения и их вложения, ответы/правки/удаление/пагинация используют прежние маршруты
и React-компоненты — отдельной системы сообщений для групп нет.

## Проверки

```sh
PORT=3102 APP_ORIGIN=http://localhost:3102 MEDIA_CHAT_DIST_DIR=.next/groups-check MEDIA_CLEANUP_ENABLED=false npm run dev
# другой терминал
node scripts/verify-groups-avatars.mjs
npm test
npx tsc --noEmit
npm run lint
```

Интеграционный тест создаёт четыре уникальных временных аккаунта, свои диалоги и
файлы. finally удаляет только его фикстуры. Перед повтором перезапустить тестовый
сервер, чтобы не упираться в штатный лимит регистрации. Не запускать на production
с реальными регистрациями. Для Chrome нужен Playwright Core во временной папке,
как в остальных скриптах проекта; FFmpeg нужен для маленького тестового видео.
Для HTTPS задаётся VERIFY_URL. Результаты текущих прогонов — в V1-PROGRESS.md.

## Готовность и ограничения

Это функциональное расширение существующего веб-приложения; Electron-зависимости
не добавлялись. До упаковки нужны ручная проверка на физических устройствах,
решение о постоянном сервере/домене и проверка сессии/выбора файлов в оболочке.
Временный localhost.run не заменяет постоянный backend. Push-уведомления/прочтения,
групповые приглашения по ссылке, модерация чужих сообщений и группы >50 участников
не входят в этот этап. Аватарки корректируют квадратную область ползунками, без
отдельного тяжёлого графического редактора. Оригиналы аватарок не хранятся.

## Внешний запуск

Временный публичный процесс использует изолированную production-сборку:

```sh
npm run build:share
npm run share
```

Скрипт печатает актуальный адрес. localhost.run может сменить домен во время работы:
старый адрес после этого даёт 502/обрыв соединения. Скрипт учитывает новый адрес и
перезапускает Node с актуальным APP_ORIGIN, но уже отправленная старая ссылка не
становится постоянной. Для проверок предусмотрены короткие прогоны:

```sh
VERIFY_URL=https://АДРЕС VERIFY_FIXTURES_VIA_DB=1 VERIFY_API_ONLY=1 node scripts/verify-groups-avatars.mjs
VERIFY_URL=https://АДРЕС node scripts/verify-groups-https-ui.mjs
```

Они используют только свои временные аккаунты и файлы, затем очищают их. В режиме
VERIFY_FIXTURES_VIA_DB аккаунты создаются как фикстуры в локальной dev-БД, а вход,
все операции и Socket.IO проверяются через HTTPS. Это сохраняет лимит регистраций
для реальных пользователей. Предыдущие неудачные HTTPS-прогоны не отмечаются как
успешные: внешний сервис возвращал 502/закрывал TLS-соединение при смене домена.
