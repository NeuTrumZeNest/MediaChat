# Контекстное меню, ответы и редактирование

Работает в текущем общем чате. Меню открывается стандартным contextmenu (правый клик, в том числе двухпальцевый клик macOS), удержанием касания 550 мс или Shift+F10/клавишей контекстного меню на сфокусированном сообщении. Сдвиг касания больше 10 px отменяет удержание, чтобы не мешать прокрутке. После удержания обычный click подавляется, поэтому фото/видео не открывается одновременно с меню.

Меню ограничено границами viewport; закрывается по клику снаружи, Escape, Tab, пользовательской прокрутке или изменению размера окна. Стрелки вверх/вниз, Home/End выбирают доступный пункт; Enter запускает действие. Короткие анимации учитывают prefers-reduced-motion.

## Действия

- Скопировать: исходный текст сообщения, Clipboard API с fallback для старых/небезопасных контекстов. Успех/ошибка показываются сообщением статуса. Для вложения без текста пункт недоступен с пояснением.
- Ответить: карточка автора и краткого текста/обозначения вложения над композером, отмена крестиком. В сообщении отображается цитата; нажатие переводит к оригиналу, ставит фокус и подсвечивает его. Если оригинала нет в загруженной истории, показывается понятный статус. Для пачки вложений ответ, как и подпись, относится к первому отправленному сообщению.
- Изменить: текст собственного сообщения, включая подписи к изображениям, альбомам, аудио, видео и файлам (ответы тоже можно менять). Отдельная форма сохраняет обычный черновик, вложения и выбранный ответ. Enter сохраняет, Shift+Enter добавляет строку, Escape отменяет. После сохранения есть отметка «изменено»; цитаты в загруженном чате показывают актуальный текст оригинала.

## База и сервер

Добавлены nullable Message.replyToId и Message.editedAt, self-relation replyTo/replies и индекс replyToId. Внешний ключ ON DELETE SET NULL сохраняет ответ при удалении оригинала. Миграция `20261112T0956_message_replies_and_edits` содержит только аддитивные операции; исходные данные не переписывались и не удалялись. Живой контракт проверен до миграции, DDL просмотрен, migration check прошёл.

`chat-message` принимает числовой replyToId. Источник должен существовать и принадлежать тому же чату; пока разрешён только общий чат. Нельзя сослаться на личное сообщение даже при знании идентификатора. В истории summary формируется только для источника в том же conversationId: приватный текст не попадёт в публичный ответ даже при некорректной ссылке в БД. Автор определяется сессией, клиентские author/userId не используются.

`edit-message` проверяет JWT-сессию Socket.IO, срок действия, существование пользователя, доступный чат, автора, отсутствие вложений и текст 1–4000 символов. Клиент передаёт expectedText/expectedEditedAt; условный UPDATE предотвращает потерю конкурирующей правки. Одна успешная правка побеждает, вторая получает отказ. Время правки строго растёт даже для очень быстрых изменений или отката системных часов. Повтор сохранения того же текста идемпотентен. Ограничение — 30 попыток изменения в минуту на пользователя.

Изменение доставляется событием message-edited в комнату соответствующего чата (сейчас general). Идентификатор автора/вложения/ссылка ответа не меняются. Ответы используют существующий уникальный clientMessageId и механизм подтверждений. На клиенте кеш версий не позволяет позднему HTTP-ответу истории или подтверждению отправки затереть более новую realtime-правку; обновления не создают новых сообщений.

Для будущих личных/групповых переписок формат ссылки, summary, компонентов и имена комнат готовы к использованию. Перед включением этих переписок нужно подключить проверки membership и вступление в комнаты в их собственных маршрутах. На этом этапе личные переписки не реализовывались.

## Проверки и ограничения

Проверены 24 автоматических теста, TypeScript, ESLint, production-сборка и синтаксис server.js. В настоящем Chrome с двумя аккаунтами проверены правый клик, копирование/статус, отключённые действия, клавиатура, Escape/клик снаружи, границы окна, ответы на текст/изображение, переход к оригиналу, сохранение/отмена редактирования, сохранность черновика, realtime/перезагрузка, конкурирующие изменения и повторные сообщения без дубликатов. Серверные проверки включают чужое авторство, другой чат, недоступный источник, подмену автора, некорректные данные, приватную цитату и истечение Socket.IO-сессии.

Долгое нажатие и отмена при движении проверены через эмуляцию touch в настоящем Chrome, не на физическом iPhone. Физический двухпальцевый клик и настоящий Safari/macOS/iOS отдельно не проверялись; macOS использует тот же обработчик contextmenu. На нестандартных HTTP-origin/при запрете буфера браузером копирование может быть запрещено — в таком случае показывается ошибка. Сами вложения не заменяются; их подпись можно добавить, изменить или убрать. Без вложения сообщение остаётся непустым. Прокрутка к оригиналу работает по загруженной истории; подгрузка произвольного сообщения вне истории пока не реализована.

После обновления перезапустить custom Node-сервер (`Ctrl+C`, `npm run dev`) и обновить страницу. Клиентский Fast Refresh не обновляет обработчики server.js.

Меню дополнено удалением собственных сообщений у всех с подтверждением. Удалённые цитаты и безопасная очистка вложений описаны в [MESSAGE-DELETION.md](./MESSAGE-DELETION.md).
