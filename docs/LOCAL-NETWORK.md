# Работа MediaChat в домашней сети

## Запуск

На MacBook из существующего проекта:

```sh
cd ~/Desktop/media-chat
npm run dev
```

Если порт 3000 занят прежним запуском, остановите его в его терминале через Ctrl+C. Не запускайте `share` и `dev` на одном порту одновременно.

На Mac откройте `http://localhost:3000`. На телефоне в той же Wi-Fi сети откройте `http://192.168.0.103:3000` (подставьте текущий Wi-Fi IPv4 Mac из системных настроек сети). Адрес может измениться после переподключения роутера. Mac должен оставаться включённым. Гостевая Wi-Fi сеть с изоляцией клиентов может блокировать соединение. Не отключайте системный брандмауэр.

## Разрешённые источники

В режиме разработки разрешены точные HTTP-адреса `localhost`, `127.0.0.1`, `[::1]` и текущих частных IPv4-интерфейсов Mac на `PORT` (по умолчанию 3000). Остальные адреса подсети автоматически не разрешаются.

Дополнительные адреса можно перечислить в **существующем приватном** `.env` или `.env.local`:

```dotenv
APP_ALLOWED_ORIGINS=http://192.168.0.103:3000,https://chat.example.com
```

Указывайте точный origin: протокол, имя/IP, нестандартный порт; без завершающего `/`, пути, маски и реквизитов доступа. Для отключения автоматического добавления LAN-интерфейсов задайте `APP_ALLOW_LAN=false`. После изменения настроек перезапустите сервер.

В production автоматические локальные адреса отключены: требуется `APP_ORIGIN` и/или `APP_ALLOWED_ORIGINS`. Скрипт `share` устанавливает публичный `APP_ORIGIN` самостоятельно. Удаляйте из конфигурации больше не используемые внешние адреса. Шаблон переменных — `.env.example`; **не заменяйте им существующий файл с подключением к БД и секретом сессии**.

Проверка запросов и Socket.IO использует единый список. Внутренний адрес Next.js `0.0.0.0` не является адресом браузера. `Host` только сверяется со списком и не расширяет его; `X-Forwarded-Host` не используется для установления доверия. JWT и проверки доступа к перепискам и вложениям продолжают выполняться отдельно.

Некорректный или `null` Origin отклоняется. При отсутствии Origin браузер должен предоставить допустимый Referer; cross-site/same-site запросы отклоняются. Небраузерные JSON/octet-stream клиенты без Fetch Metadata допускаются только с разрешённым Host и обычной авторизацией соответствующего API. Для multipart API-клиент должен отправить Origin явно.

## Проверки исправления (20 ноября 2026)

Исходный POST создания диалога был оборван после ручной правки: отсутствовали создание, обработка ошибок и закрывающая скобка. Обработчик восстановлен из существующей индексированной версии Git с сохранением остальных изменений. Прежний отказ 403 возникал из-за сравнения внешнего Origin с внутренним адресом Next.js.

Регрессии:

```sh
npm test
npx tsc --noEmit
npm run lint
# При запущенном проверочном сервере на 3102:
node scripts/verify-origin-lan.mjs
```

Интеграционные скрипты создают и удаляют только собственные временные данные; требуют работающую БД. Скрипт Origin использует актуальный LAN-интерфейс и порт 3102. Полные сценарии `verify-direct-messages.mjs` и `verify-groups-avatars.mjs` поддерживают `VERIFY_URL`; браузерные части требуют Chrome и Playwright. `VERIFY_FIXTURES_VIA_DB=1` создаёт тестовые учётные записи непосредственно в БД для повторных прогонов, не отключая ограничение регистрации приложения.

Реальный Android и физическое отключение Wi-Fi автоматически не проверяются. Вручную проверьте на двух телефонах регистрацию/вход, поиск и профиль, личный диалог, все типы вложений, аватарки и группу. Выключите Wi-Fi на одном телефоне, затем включите: соединение и новые сообщения должны восстановиться. Третий аккаунт не должен видеть чужую переписку и скачивать её вложения. Попытка начать диалог с собой должна возвращать понятную ошибку, а не 403.
