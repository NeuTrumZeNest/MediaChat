# Альбомы и пакетная отправка

Через существующее меню вложений можно выбрать несколько фотографий, треков, видео или обычных файлов. Повторный выбор добавляет файлы к существующей очереди.

| Тип | В очереди | В одном сообщении | Максимум на файл |
| --- | ---: | ---: | ---: |
| Изображения | Без ограничения количества | 9 | 25 МиБ |
| Музыка | 20 | 1 | 50 МиБ |
| Видео | 10 | 1 | 50 МиБ |
| Документ или обычный файл | 20 | 1 | 2 ГиБ |

10 фотографий превращаются в альбом из девяти и отдельную фотографию; 30 — в группы 9 + 9 + 9 + 3. Порядок соответствует порядку, переданному проводником. Подпись добавляется только к первому сообщению. Каждый снимок открывается прежним просмотрщиком с возможностью скачать оригинал. Видео и музыка отправляются отдельными сообщениями и используют существующие плееры.

Перед отправкой отображаются выбранные файлы, их размер и миниатюры изображений/видео; файлы можно убрать. Новое открытие проводника дополняет текущий выбор. В одной очереди можно смешивать фотографии, видео, музыку и документы; лимиты треков, видео и файлов проверяются по всей очереди, включая ранее выбранные.

## Хранение и права

`MessageImage` хранит связь с `Message`, URL и позицию. Поле `Message.imageUrl` сохранено для совместимости: у новых альбомов содержит первое изображение. Старая история без строк `MessageImage` отображается как раньше. Миграция `20261112T0742_add_image_albums` только создаёт таблицу, ограничения и индексы; существующие записи не изменяет.

Сервер принимает `imageUrls` до девяти уникальных изображений, проверяет владельца каждого файла до записи. Сообщение и связи сохраняются в одной транзакции. Проверка чтения учитывает и старые одиночные фотографии, и все элементы альбома. Для приватной переписки требуется участие; возможность читать файл не даёт права отправить его как своё вложение.

## Загрузка и повторы

Файлы загружаются последовательно в порядке добавления через действующие защищённые маршруты. Соседние фотографии группируются в альбомы до девяти, остальные вложения отправляются отдельными сообщениями. Показываются номер сообщения, имя текущего файла и прогресс его загрузки; после загрузки видео сервер ещё проверяет содержимое и создаёт превью. Исходные лимиты и проверки форматов сохранены.

Каждой группе присваивается стабильный `clientMessageId`. При ошибке сохраняются URL завершённых загрузок и позиция в очереди. Повторное нажатие отправки продолжает очередь; сервер возвращает уже сохранённое сообщение при потере подтверждения. Уже отправленные файлы удаляются из предпросмотра. При сбое загрузки остальные файлы остаются в черновике: проблемный файл можно убрать отдельно. При потере подтверждения уже отправленного сообщения редактирование временно заблокировано, чтобы повторная попытка использовала неизменные данные. Удаление остатка не удаляет отправленные сообщения.

Очередь не восстанавливается после перезагрузки страницы. Незакреплённые загрузки после отмены пока не очищаются фоновым заданием. Существующий лимит видео — десять попыток загрузки за десять минут на пользователя; повтор после неудачной загрузки тоже учитывается. Публичная история пока загружается целиком — её пагинация остаётся отдельной задачей стабилизации.

## Проверка

- `npm test`: разбиение пачек, валидация каждого файла, лимиты, совместимость старых сообщений и порядок фотографий.
- `node scripts/verify-attachment-batch.mjs`: отдельный тестовый сервер (по умолчанию порт 3102), локальная PostgreSQL, FFmpeg и Chrome. Скрипт создаёт два временных аккаунта и файлы, затем удаляет только свои данные. Проверяет реальные загрузки, Socket.IO, 9+1, потерю подтверждения, сбой второго трека, MP4/WebM, обновление истории, права приватного альбома и узкий экран.
- Путь Playwright Core задаётся `PLAYWRIGHT_MODULE`, Chrome — `CHROME_PATH`, сервер — `VERIFY_URL`. По умолчанию используются локальные пути проверочной среды; эти инструменты не добавлены в зависимости приложения.

После обновления необходимо перезапустить собственный Node-сервер: изменения обработчиков `server.js` не применяются через React Fast Refresh.

Файлы при выборе проверяются независимо. Неподходящие пропускаются с объяснением причины, остальные остаются в предпросмотре. Если весь новый выбор отклонён, предыдущий черновик сохраняется. Лимит оригинала изображения — 25 МиБ; оптимизированное превью создаётся отдельно, оригинал сохраняется без перекодирования.


## Файлы неизвестных форматов

Пункт «Документ или архив» позволяет выбрать любые файлы, в том числе несколько за раз. При выборе неизвестного расширения через медиа-пункт файл тоже попадает в очередь как обычный документ, если его размер не превышает 2 ГиБ. Форматы с поддерживаемым расширением проходят свои проверки. Если формат, кодек или содержимое не поддерживается, вложение автоматически загружается обычным файлом без предпросмотра.

Неизвестные типы хранятся под именем UUID.bin, исходное имя и расширение сохраняются в метаданных. Они выдаются только с `application/octet-stream`, `Content-Disposition: attachment`, `nosniff` и CSP `sandbox`. Содержимое не исполняется и не распаковывается сервером. Карточка содержит белую иконку листа, исходное имя, размер и скачивание. Файлы без расширения также поддерживаются.

PDF, TXT/CSV и ZIP/Office до 25 МиБ сохраняют существующие проверки содержимого. Файлы большего размера принимаются как непрозрачные данные без распаковки/полной проверки; выдаются как application/octet-stream только для скачивания. Права владельца при публикации и права чтения при скачивании действуют для всех форматов.

Потоковая загрузка документов до 2 ГиБ: [LARGE-FILES.md](./LARGE-FILES.md).


## Автоматический переход в обычный файл

Проверка при выборе сразу переводит неподдерживаемый формат/MIME или слишком большое для медиаплеера вложение в обычный файл до 2 ГиБ. Если о несовместимости стало известно после проверки на сервере (например, MP4 с неподдерживаемым кодеком), клиент повторяет загрузку через потоковый маршрут документов с `asFile=1`. Такой файл хранится как UUID.bin с исходным именем/расширением, меткой opaque и MIME application/octet-stream. Выдача только для скачивания и прежние проверки доступа сохранены. Кодек не меняется, перекодирования нет.

Небольшой PDF/ZIP, не прошедший проверку, также можно передать как непрозрачный файл. Это не подтверждает его исправность: MediaChat лишь передаёт исходные байты. Небезопасное имя, пустое тело и превышение 2 ГиБ по-прежнему отклоняются.

Если элемент альбома стал файлом, до публикации сообщения группа разбивается в исходном порядке на фотографии и отдельные файловые сообщения. Сохранённые URL переиспользуются, подпись остаётся только у первого сообщения. Повторы после потери подтверждения сохраняют свои идентификаторы.

401/403, 429, ошибки сети, ожидания и 5xx не вызывают автоматический переход: черновик остаётся для повторной попытки. Вторая загрузка как файл также может завершиться ошибкой; исходный файл остаётся в очереди с выбранным режимом обычного файла.
