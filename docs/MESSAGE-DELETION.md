# Удаление сообщений и очистка серверных копий

## Поведение для пользователя

В контекстном меню есть «Удалить». Удалить можно только своё сообщение текущего общего чата. Действие требует подтверждения «Удалить у всех», после которого сообщение исчезает у всех подключённых участников и после перезагрузки. Это необратимое действие; восстановления в интерфейсе нет.

Работающие проигрыватели удалённого вложения останавливаются/закрываются, просмотр изображения закрывается. В ответах вместо содержимого оригинала показывается «Сообщение удалено». При временном отсутствии связи подтверждение показывает ошибку, сообщение остаётся на месте и удаление можно повторить.

Удаление касается копий в приватной папке MediaChat `uploads/`:

- Фото: оригинал, WebP-превью и JSON-метаданные.
- Аудио: оригинал и метаданные.
- Видео: оригинал, миниатюра и метаданные.
- Документ/архив/обычный файл: оригинал и метаданные.

Файлы на компьютере отправителя не затрагиваются. Уже скачанные получателями копии и старые резервные копии автоматически отозвать нельзя. Уже открытый серверный поток скачивания может завершиться; диск окончательно освобождается после закрытия последнего открытого файла ОС.

Если один URL используется несколькими сообщениями (включая другой/приватный чат), файл сохраняется до удаления последней ссылки. Отдельный пункт «очистить всё в uploads» не нужен: он мог бы повредить сохранённую историю. Очистка работает только с проверенными неиспользуемыми файлами.

## Сохранение и защита от повторов

В транзакции проверяется автор/доступный чат, очищаются текст, все URL, строки альбома, время правки и собственная ссылка ответа. Ставится Message.deletedAt. В БД остаются служебные ID/автор/время/идентификатор отправки, но не текст и не вложение. Эта небольшая отметка предотвращает восстановление удалённого сообщения при повторной доставке старой отправки. Она не является сохранённой копией содержимого сообщения.

В той же транзакции создаются MediaCleanupJob с уникальным URL. После commit событие message-deleted доставляется в комнату чата, а сервер пытается удалить файл и производные. Повтор удаления идемпотентен. Нельзя удалить чужое или приватное сообщение, подставив ID/userId; сервер проверяет сессию и автора. Действует лимит 30 попыток в минуту.

Прежде чем удалить файл, обработчик ещё раз проверяет все типы ссылок и альбомы в PostgreSQL. Проверка по UUID сохраняет и исторические относительные/абсолютные URL того же файла. Прикрепление и очистка используют одни и те же транзакционные advisory locks по URL. Поэтому новое сообщение не может сохранить ссылку на файл, удаляемый очисткой. Проверки касаются всех чатов, а не только доступной удаляющему пользователю истории. Метаданные сверяются с владельцем и UUID; имена пользователя не используются как путь. Ссылки вне разрешённых маршрутов, symlink и неподтверждённые метаданные не дают права удаления.

Метаданные удаляются последними: после частичного сбоя можно безопасно повторить операцию. Неудача сохраняется в очереди с attempts/lastError. Очередь переживает перезапуск, проверяется при запуске и раз в минуту. Это не транзакция между PostgreSQL и файловой системой, поэтому при сбое копия может временно остаться на диске до повтора.

История возвращает активные сообщения и ID удалённых. Клиент не возвращает удалённые сообщения из поздних HTTP-ответов/Socket.IO, обновляет цитаты и восстанавливает пропущенные удаления после reconnect. Ссылка на уже удалённый оригинал не допускает нового ответа. Если источник удалён во время загрузки ответа, файлы черновика остаются доступными для повторной отправки без старой цитаты.

## Автоматическая и ручная очистка

Раз в час проверяются оригиналы, метаданные и staging. Загрузки без ссылок на сообщения удаляются только если оригинал, метаданные и производные не менялись минимум **24 часа**. Это запас для выбранных файлов, незавершённых отправок и повторов. Недавние загрузки и файлы из сохранённой истории остаются. Старые staging-файлы тоже очищаются; активная загрузка ограничена часом и под этот порог не попадает. Превью с оставшимися валидными метаданными можно убрать даже при отсутствии оригинала.

Файлы с отсутствующими/повреждёнными метаданными и непроверяемым владельцем остаются на месте со статусом unverified — их следует сначала проверить вручную. Строгая проверка UUID/типов также оставляет посторонние файлы. Полноценной очистки произвольных файлов из uploads команда не делает.

Из корня проекта:

```sh
npm run media:cleanup
```

Это **dry-run**, отчёт без удаления. Показывает задания, результаты проверки, предполагаемые удаляемые файлы и объём.

```sh
npm run media:cleanup -- --apply
```

Применяет безопасную очистку: повторяет очередь и удаляет подтверждённые старые неиспользуемые копии. Данные PostgreSQL/сохранённые сообщения не сбрасывает. Команда может работать с запущенным сервером благодаря тем же PostgreSQL-locks.

`MEDIA_CLEANUP_ENABLED=false` отключает плановую фоновую очистку/стартовый повтор очереди. Очистка вложений при явном удалении сообщения по-прежнему выполняется. После обновления нужен перезапуск custom Node-сервера.

## Файлы

- `server.js`: delete-message, транзакционные ссылки/блокировки, очередь и расписание; запрет редактирования/новых ответов на удалённое.
- `app/page.tsx`, `MessageActions.tsx`, `MessageActions.module.css`, новый `MessageDeleteDialog.tsx`, `MediaChatImage.tsx` (закрытие удалённого кадра при перелистывании): действие, подтверждение, ошибки, realtime, остановка плеера.
- `message-merge.ts`, `message-actions.ts`, API истории: защита от восстановления удалённого и удалённые цитаты.
- Новые `src/lib/media-locks.ts`, `media-cleanup.ts`: синхронизация и безопасное удаление.
- Новая `MediaCleanupJob`, Message.deletedAt, контракт/артефакты и миграция `20261112T1034_message_deletion_and_media_cleanup`. Добавляющая миграция проверена до применения; старые записи/файлы ею не изменяются.
- Маршруты выдачи audio/documents, `image-storage.ts`, `video-response.ts`: учитывают только активные сообщения при проверке доступа.
- `scripts/cleanup-media.mjs`, npm-команда `media:cleanup`.
- `tests/message-deletion.test.ts`, `scripts/verify-message-deletion.mjs`, README и отчёт прогресса.

## Проверки

27 тестов, TypeScript, ESLint и production-сборка. Настоящий Chrome с двумя временными аккаунтами: подтверждение/отмена, отказ чужому/приватному/неверному ID, realtime/перезагрузка, удалённая цитата, отсутствие восстановления старым nonce. Проверены удаление каждого типа медиа с производными, остановка проигрывания/просмотра, сохранение общего файла до последней ссылки, durable retry и уже существующее задание очереди.

Очистка старых файлов тестируется в отдельной временной папке, с выключенной плановой очисткой реальных пользовательских загрузок на тестовом сервере. Проверяются dry-run/apply, 24-часовой порог, сохранность свежих и приватных используемых файлов, оставшееся превью, отказ для неизвестных метаданных и гонка attach/cleanup. Реальная существующая история для очистки во время разработки не использовалась.

Safari/настоящий телефон отдельно не проверялись. Личные переписки и групповое администрирование/удаление чужих сообщений на этом этапе не добавлялись.
