# Обычные файлы и архивы до 2 ГиБ

Лимит одного обычного файла/документа, ZIP или RAR — 2 147 483 648 байт. Фото остаются до 25 МиБ, аудио/видео — до 50 МиБ. Очередь содержит до 20 обычных файлов. В пользовательском интерфейсе размер в гигабайтах отображается как «ГБ».

## Передача и хранение

`uploadDocument` отправляет исходный File как тело XHR в `POST /api/documents/upload?name=...` с прогрессом. Маршрут проверяет сессию/Origin и записывает тело небольшими блоками на диск через `document-stream.ts`, без накопления всего файла в памяти. Ограничение проверяется по фактическим байтам, даже без Content-Length. Ложная длина, превышение, пустое тело, отмена и обрыв отклоняются. Незавершённый файл и временные метаданные удаляются; опубликованные URL появляются только после завершения записи и проверок.

Маленькие файлы до 25 МиБ проходят прежнюю проверку в памяти (PDF, UTF-8, ZIP/Office и CRC). Крупные файлы и архивы принимаются без распаковки и полной проверки содержимого. Для них не действует прежнее ограничение ZIP на 100 МиБ после распаковки. Это хранение/передача исходного файла, а не подтверждение исправности архива. Выдача больших файлов — только `application/octet-stream` + `attachment`, с `nosniff`, CSP sandbox и проверкой доступа. Крупные RAR/ZIP не открываются и не исполняются сервером.

Старый multipart-маршрут без параметра name совместим с файлами до 25 МиБ; старую страницу нужно обновить для передачи больших файлов. Не увеличивать multipart-буфер до двух гигабайт.

Одновременно: одна загрузка документа на пользователя и две на процесс сервера. Прежний rate limit — 20 попыток за десять минут. Время загрузки — до часа. `server.js` задаёт requestTimeout 61 минута, маршрут — отдельное ограничение в час. Ошибка нехватки диска возвращает 507. Очередь сохраняется при ошибке для удаления проблемного файла или повторной попытки. Докачки с прежнего байта пока нет.

## Развёртывание за nginx

После обновления перезапустить custom Node-сервер. Если перед ним стоит nginx, для файлового маршрута нужны соответствующий размер, таймауты и отключённая буферизация запроса. Пример для вставки в существующий server-блок; реальные адрес/порт должны соответствовать развёртыванию:

```nginx
location = /api/documents/upload {
    client_max_body_size 2g;
    client_body_timeout 3600s;
    proxy_http_version 1.1;
    proxy_request_buffering off;
    proxy_send_timeout 3600s;
    proxy_read_timeout 3600s;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_pass http://127.0.0.1:3000;
}
```

Проверить ограничения внешнего хостинга/CDN: настройка приложения не меняет лимиты провайдера. Загрузки и PostgreSQL по-прежнему должны находиться на постоянном приватном хранилище. Общие квоты диска на аккаунт и удаление заброшенных завершённых загрузок ещё не реализованы.

## Проверка

- `npm test`: граница 2 ГиБ без выделения гигабайтного буфера, фактический счётчик потока, ложная длина, пустой/повреждённый файл, отмена, очистка staging и права владельца.
- `node scripts/verify-large-documents.mjs`: Chrome отправляет настоящий объём 2 ГиБ из временного sparse-файла с расширением RAR. Это тест границы передачи, не валидатор RAR. Проверяются сообщение/история второго аккаунта, перезагрузка, SHA-256 потокового скачивания, отказ для 2 ГиБ + 1, старый multipart и настоящий ZIP больше 25 МиБ. Скрипт требует отдельного тестового сервера, Chrome/Playwright Core и zip; создаёт два временных аккаунта, удаляет только свои записи/файлы.
